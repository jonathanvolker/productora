# Documentacion del proyecto

## Como usar estos documentos

1. `01-alcance-funcional.md` define que debe hacer el MVP y que no debe incorporarse sin una nueva decision.
2. `02-arquitectura.md` describe la separacion entre marcas, API, panel y futuras integraciones.
3. `03-stack-tecnologico.md` fija la recomendacion tecnica inicial.
4. `04-lineamientos-desarrollo.md` establece reglas para escribir y revisar codigo.
5. `05-modelo-dominio.md` define las entidades y flujos principales sin pretender ser el esquema final.
6. `06-calidad-seguridad-operacion.md` define controles minimos para entregar software confiable.
7. `07-decisiones-pendientes.md` concentra preguntas al cliente y decisiones que bloquean presupuesto o desarrollo.
8. `08-guia-de-incorporacion.md` explica el estado actual, los comandos y el orden recomendado de avance.

## Regla de fuente de verdad

Si una solicitud contradice una decision documentada, no se implementa directamente. Se registra el cambio,
su impacto en alcance, datos, presupuesto y fechas, y se obtiene aprobacion.
